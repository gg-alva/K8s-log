Today, I continued my learning by going deeper into **Helm Charts** and exploring **Azure networking concepts**. I also gained hands-on experience with managing Kubernetes applications across multiple replicas and namespaces.

### Advanced Helm Chart Hands-on

I explored Helm Charts in more depth and practiced managing Kubernetes applications through different stages of their lifecycle.

I worked with:

* **Helm package** – Packaged Helm Charts into distributable chart archives.
* **Helm install** – Deployed applications using Helm Charts.
* **Helm upgrade** – Updated existing releases with new configurations or chart versions.
* **Helm rollback** – Reverted a release to a previous revision when required.
* **Multiple Pod replicas** – Worked with deployments running multiple replicas to understand how Helm manages scaled applications.
* **Multiple namespaces** – Deployed and managed Helm releases across different Kubernetes namespaces.

This hands-on practice helped me understand how Helm maintains **release versions and revision history**, making it easier to upgrade applications and safely roll back changes when required.

### Azure Networking

I also explored the fundamentals of **Azure networking**, focusing on how Azure provides network isolation and controls traffic between resources.

The concepts I covered include:

* **Virtual Network (VNet)** – Provides an isolated network environment for Azure resources.
* **Subnet** – Divides a VNet into smaller network segments for organizing and isolating resources.
* **Network Security Group (NSG)** – Controls inbound and outbound network traffic using security rules.
* **Application Security Group (ASG)** – Helps logically group application workloads and simplify security-rule management.

I learned how these components work together to provide **network segmentation, isolation, and controlled communication between resources**.
